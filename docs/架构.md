# go2_v4 仿真架构

## 1. 系统与边界

v4复用v3的分层与唯一负责人原则，只运行域78中的Gazebo仿真。物理场景为导入的`custom.world`，关节/接触动力学采用reference_trot。默认由Leg-KILO使用仿真雷达和IMU进行LIO定位，再由loc_pose判断位姿可信度；没有使用腿里程计融合。旧版真值定位已改为显式诊断选项。

控制台只有一个界面模板。顶部「实时导航」在当前页面、同一画布和右侧卡片中切换工作区，沿用原配色、图层和遥控，不跳转URL、不使用独立模板或iframe。旧`/realtime`和`/realtime.html`地址仅兼容返回同一模板。固定图与实时后端共用唯一StackManager、ROS域、Gazebo master和会话锁；切换运行模式必须先停止当前仿真。

## 3. 唯一负责人

| 判断 / 输出 | 唯一负责人 | 边界 |
|---|---|---|
| 仿真生命周期、进程归属 | StackManager / sim.launch.py | 一个会话、一把仿真锁 |
| 本次定位可信状态/平面TF | loc_pose，输入只取Leg-KILO的/kilo_odom | /loc_status、/loc_odom、odom→base_footprint |
| body姿态/高度TF | sim_slam_frames，输入/kilo_odom | base_footprint→base；初始地面高度参考0.35m |
| 设备物理状态/故障 | sim_bridge | 真值只作设备反馈和评价，不发布SLAM定位 |
| 点云转障碍/地面扫描 | per_scan | 外参与机身尺寸取geometry.yaml |
| `/map`地图来源 | 固定模式per_map；实时模式sim_online_mapper，二选一 | 在线mapper不读取world占据或完整保存图 |
| 实时证据和导航图融合 | per_evidence；实时模式由RealtimeEvidence子类提供profile，二选一 | 唯一发布`/per_evidence_map`、`/per_nav_map` |
| 实时工作区模式/候选意图 | sim_realtime | 只提议任务，维护网页租约；没有执行恢复动作的权限 |
| 目标执行、恢复、重试 | task_executor | 唯一发布`/mot_nav_goal`和恢复请求；blocked/start_blocked阶梯只在task_logic.LOCAL_LADDERS定义一次、由其内LocalRecovery执行一次（多点RouteExecution与单点/示教LegacyLocalHost为宿主），控制链仍单层 |
| 可达性、路径、跟随、到达 | 原mot_nav | 唯一`/mot_nav_check`，算法保持原样 |
| 哪路速度生效 | mot_cmd_mux | 手动 > 恢复 > 导航 |
| 自动速度是否限制 | safe_gate | 只限幅/置零，不生成自主动作 |
| 驱动仿真运动入口 | sim_bridge | 只消费安全速度并核对控制器/反馈 |

实时模式不启动固定图per_map；不启动原版PerEvidence的第二个副本；也没有另一路导航图发布者。集成检查通过ROS图核对关键输出的发布者数量。

## 4. 两种地图模式

固定地图模式：保存`my_map`作为先验。未确认的保存墙是代价60；观测占据/手绘硬墙是100；近期正证据过期后恢复先验而不证明空闲，时长分动态/静态：同一格连续被占据<3秒（static_min_s）的是动态、最后命中后5秒（dynamic_ttl_s）消失，≥3秒的是静态、90秒（static_ttl_s）消失；/per_evidence_map里静态=100、动态=99，两者都阻挡规划（per_evidence.nav用>=99），99/100只用于网页配色。网页图层面板经`/per_evidence_ttl_cmd`（String JSON）实时调两个时长，per_evidence校验后回显到`/per_evidence_ttl`（Go2Node关闭了参数服务，所以不用ros2 param）；仅本次运行有效。此模式保留原有感知与规划策略。

实时模式：固定600×600、5cm、原点(-15,-15)m，占30m×30m。初始化全未知；仅实际机身足迹与扫描射线观测更新。有限障碍回波前的射线路径、地面扫描可更新空闲；无回波且无地面证据仍未知。对应扫描时戳TF不可用就等待/丢弃，不使用最新位姿代替。范围相对SLAM起点；越界拒绝更新，没有实现网格自动扩展。loc_pose报告跳变时清空在线地图和近期证据，版本递增；定位非OK时暂停积累。

在线mapper维护持久二维观测地图，重复空闲观测可消除旧占据。`per_evidence`维护近期证据（动态5秒/静态90秒，见上）。实时profile把未知与当前观测占据设为导航阻挡，空闲格受近期证据覆盖；原规划器输入仍只有`/per_nav_map`。持久建图没有这些TTL；近期障碍（黄/青）消失不等于持久地图已忘记该处物体。

出生点由仿真初始化工具根据配套保存图选取；固定图模式只把该配置作为一次初始定位提示交给loc_align匹配，运行中的位姿来自Leg-KILO；在线mapping/探索不读取该保存图的占据。已观测面积是格子面积，不是完整world覆盖率。找不到安全前沿报告“暂无可达前沿”，不能宣称全部探索完成。

## 5. 实时任务与显示

`sim_realtime`有手动、单点、探索及暂停/不可达/到达状态。单点目标必须已观测为空闲并留足机身空间，再调用原规划器检查。探索检测空闲/未知边界，按信息量与观测区域距离排序，候选通过原规划器检查才交给task_executor。到达/执行失败从任务事件获取，暂时排除已访问/失败候选，再选下一目标；候选筛选不是第二套路径规划执行器。

界面显示持久地图（未知灰、空闲白、占据深色）、原始实时扫描红点、近期障碍青色`#00bcd4`、前沿候选与原规划器路径；青色图像仅在显示时加宽一格，便于与红色扫描点同时辨认，不改变导航占据/碰撞尺寸。遥控、定位状态、位置、观测面积、安全状态和快照保存均位于右侧。主网页恢复默认显示红色扫描，近期障碍仍青色。实时模式没有网页3D点云。

网格驻留规模：600²=36万格，mapper score约0.72MB、seen约0.36MB，每张OccupancyGrid原始数据约0.36MB；地图约2Hz发布，PNG按版本拉取。前沿候选限制12个，扫描配对队列各最多6条。不把高频原始云转发给网页。此为容量预算，CPU/RSS峰值尚需更长运行测量。

## 6. 启动、看门狗和停止

```text
go2_env.sh（ROS_DOMAIN_ID=78 / localhost / master11348）
  → sim_up.sh → sim_console.py（先核实并收尾旧v4会话、确认端口释放）
  → web_server:10087 → 唯一StackManager
  → sim.launch.py mode:=nav|realtime
  → 暂停物理 → spawn成功 → 广播器 → 站立JTC → effort
  → 5秒站立轨迹 → reference_trot交接/反馈稳定 → SIM_GAIT_READY
  → 开放真实IMU → 至少50帧IMU后开放瞬时点云 → Leg-KILO
  → loc_pose连续OK2秒 + 地图/扫描就绪 → SIM_READY
```

固定图模式随后由loc_align使用初始提示完成匹配；实时工作区采用SLAM起点为map原点。实时工作区还需要在线地图、扫描、任务与定位新鲜，才允许发自动任务。运行中的自动控制由独立于ROS仿真时间的网页租约保护：超过3秒收不到当前控制页面的心跳就取消任务、进入暂停；另一个仅查看的页面不能替控制页面续租。定位/扫描反馈过期或任务/导航图反馈失联也暂停；不会自行恢复运动。手动按键以10Hz发命令，松开/本页面失焦发送零速；控制页面失焦请求暂停，查看页面失焦不会取消其他页面的任务。设备桥0.3秒命令超时停机，SLAM健康不满足时也禁止运动。

手动遥控没有障碍防撞限制，遵守原safe_gate手动策略；自动导航仍受定位、扫描新鲜度、障碍刹停限制。切到手动时先取消自动任务，收到任务空闲后开放按键。

任一核心节点或Gazebo窗口退出即整栈Shutdown。启动60秒未SIM_READY由管理器停止。网页退出等待其会话收尾；监护线程按`GO2_SIM_SESSION`、PID启动时间核对进程。仅信号本次归属进程，不按名字批量杀。`runs/.simulation.lock`为flock，文件保留不代表锁被占用。

构建/测试/仿真检查运行在`tools/run_bounded.py`下，记录启动、心跳、退出和超时。每阶段检查健康及进程/端口释放；结果写入record.md和docs/records。地图快照保存在新run的`maps/<唯一时间>/`，不覆盖用户保存地图。

## 7. 模型与验证边界

world原件在`src/go2_sim/worlds/`；run内生成simulation.world，保留房间几何、移除编辑器state快照，再spawn本次Go2。惯量、关节/足端接触、站立和对角步态来自internship。雷达固定在base，光心随实际body高度/roll/pitch运动；外参唯一来源geometry.yaml。

当前二维建图使用仿真扫描与Leg-KILO估计位姿。已完成短距离SLAM定位、固定图对齐/导航及实时前沿移动增图验证；全world覆盖、复杂门洞、动态人群、长时性能和真实传感器/真机仍需专门验证。历史真值阶段不作为SLAM验证，失败和每轮证据见record.md。


## 8. Leg-KILO仿真接入

```text
Gazebo body IMU /go2/imu (250Hz设置) ─┐
                                   ├─ sim_slam_inputs ─► Leg-KILO（原算法）
Gazebo /sim/mid360_points (10Hz) ────┘                    │
         原始雷达轴系 + geometry.yaml外参                │ /kilo_odom
                                                        ▼
                        ┌────────────────────────────────────────┐
                        │ loc_pose：唯一可信度判据及平面里程计TF │
                        │ sim_slam_frames：body姿态/高度TF        │
                        └────────────────────────────────────────┘
                         │ /loc_status、/loc_odom、定位TF
                         ▼
                      建图 / 前沿候选 / 原规划与跟随

/sim/model_states → sim_bridge → /dev_state、故障、/sim/ground_truth_odom、body_motion.csv；sim_bridge另外只做日志地写 runs/<run>/cmd_trace.csv（/dev_teleop_cmd_vel、/mot_nav_cmd_vel、/mot_recover_cmd_vel、/mot_cmd_vel、/safe_cmd_vel、/safe_status输出、/sim/cmd_vel 的速度指令，列：sim_s,topic,vx,vy,wz,limiting,reason），用于区分“指令太小/被限速/被丢弃”，不参与控制
                           （物理反馈/误差对照，不进入导航位姿TF）
```

Gazebo射线是同一时刻的快照，输入适配器只保留原xyz/时戳/坐标系并补零的intensity/time字段，不能伪造旋转扫描时序。过滤机身点时使用geometry.yaml外参，但输出点仍在原始mid360_link中；Leg-KILO自身应用同一外参一次。IMU使用传感器实际角速度/加速度，不由真值位姿差分生成。仿真配置关闭“丢弃重复IMU”以保留静止时的时间覆盖；原算法源码不改。

SLAM起点body z=0；sim_slam_frames采用0.35m初始地面高度参考再加SLAM相对z，roll/pitch也取SLAM。该初始参考是明示配置近似，不是在线真值补偿；台阶/高度基准仍需专门验证。网页二维格使用前端里程计投影，不是后端回环优化图的重投影；后端全局图单独导出，长距离回环一致性尚未验证。每run生成独立配置、外参/输入topic快照，Leg-KILO退出自动保存全局图、前/后端轨迹，并复制runtime/glog。

退出预算：Leg-KILO优雅退出/导出40秒，管理器55秒后才升级，网页等待65秒，sim_console和检查脚本75秒，仿真检查外层收尾85秒。任何SLAM核心退出都会停止整次仿真；不回退Gazebo定位。显式`localisation:=ground_truth`只用于诊断对照，网页必须标明该来源。


## 9. 网页会话隔离与初始定位反馈

StackManager每次启动公开新的session_id。常驻WebNode按会话身份（不能只按mode）清空位姿、原始状态、扫描、标记、路径、显示图层和对齐状态，并在ROS执行线程重建TF Buffer/监听，重新订阅当前发布者的静态TF。更新显示采用稳态计时器；未来时间戳不能算新鲜。网页扫描显示最多保留6帧、等待自身TF不超过1秒，LIO滞后时重试而非丢弃所有红点；过期则清除。帧计算完成时再次核对会话，前端图像回调也核对session_id；新SLAM定位到达前显示等待，绝不保留上一轮箭头。实时坐标原点是本轮SLAM起点，不是上轮固定图的map→odom。

手动初始定位仍由loc_align裁决。其ALIGN_OK/WEAK/FAIL事件带request_stamp_ns；网页用它匹配本次请求，并等待对应的新map→odom TF已经接收，才确认显示结果。/api/state的alignment字段有request_id、requested、state（unaligned/pending/ok/weak/failed）、reason及原事件fields。提交后顶栏/定位卡显示定位中，完成或弱对齐/失败明确变化；8秒没有完成反馈则超时失败。SLAM连续健康与地图对齐分别表示，不用旧的OK掩盖正在处理的初始定位。活动任务先结束才能重新给初始定位，对齐未完成不得开始新固定图任务。

运行元数据run.yaml通过临时文件原子替换发布，网页在文件未就绪时重试；发现运行目录不意味着配置已经写完。


## 网页反馈与启动适配（2026-11-11）

- 可选目标yaw经网页→sim_realtime→/goal_pose传到原task_executor；无yaw维持全零四元数的无终点朝向约定。原规划/跟随算法和各层唯一控制权不变。
- 固定图Leg-KILO栈启动原loc_map_check，使用最多1秒扫描队列选择最新可获得自身时戳TF的扫描，绝不回退最新位姿。它只测吻合分数，状态仍由loc_pose判断；网页只显示3秒内分数。实时模式不启用静态图吻合分数。
- 网页实际轨迹按会话记录，初始对齐清空，后端最多40000点、API最多约3000点；10Hz位姿采集/轮询与150ms延迟插值只改善显示，不参与控制。轨迹API含session_id，旧会话响应作废。
- sim_startup只负责原控制器load/configure的依赖编排，并继承原StandCommand。减少多次Python/DDS启动，不增加控制器或改变原站立/trot/SLAM就绪门槛。失败使launch关闭当前归属栈。


2026-11-11扫描根因修复：统一在唯一`go2_per/per_scan`所有者内修正点云→机身投影的时间一致性与地面拟合生命周期。保留原per_logic外参/射线分桶/高度带/拟合规则；最多8帧、1秒队列，使用扫描自身时戳TF，处理最新可解帧，丢过期和旧帧。每帧覆盖plane（包括无法拟合的零参考），不将上一机身帧的plane用于下一帧。没有新增仿真派生扫描节点或用真值修正扫描；固定/实时共用此处修复。网页蓝色规划路径仅执行中显示，实际轨迹继续后台存档，导航画布不绘制红色尾迹；建图示教线不变。任务遥控作为第四子页签移动唯一teleCard，不增加控制入口或发布者。

普通多段导航由唯一task_executor内的RouteExecution组件管理：目标区域经原/mot_nav_check确认被占、明确导航失败或20秒实际空间无进展时，中间点本圈跳过，只有原始最后一点搜索经过原服务验证的附近落点。每点90秒非暂停总预算和最多5个末点候选执行上限；DEGRADED不豁免，LOST撤运动并暂停。取消本圈末尾额外补跑；循环下一圈重新尝试所有原始点，替代点不改写任务列表。整圈无到达仍保留原LOOP_STOP保护。

中间点“经过就算过”：中间点到达半径max(自身, route_pass_radius_m=0.6)且不转朝向，最后一点保持原半径与朝向；绕大圈上限（只用于多段）：每点记录原规划器代价最小值，超过max(1.5×,+2米)持续3秒即detour_too_long（用/mot_nav_check的leg_m）；单点/示教不限制绕大圈。/mot_nav_check响应另含leg_path_off/x/y（各段A*路径，仅供显示）；网页每2秒向它询问当前目标之后各点的航段并以虚线显示（route_preview，仅显示、不参与控制）；/viz_task_markers新增ns=wp_yaw的ARROW（用户给的朝向，网页画成圈内箭头）。

多段进展按loc_pose实际空间推进计时，进展=近20秒内机器人曾离当前位置至少0.4米（route_progress_m/route_no_progress_s）；原地蠕动、转向和小幅摆动无进展，原路退出死路走廊算进展，大圈由每点90秒预算兜底；路径缩短/重规划/换goal编号不刷新窗口，局部脱困结束后有10秒宽限。单点/示教的“没进展”判据改为同一滑动窗口（no_progress_s=20/no_progress_m=0.4，hold 2秒），no_path/no_progress走“后退→转向”（SINGLE_LADDERS，共用LocalRecovery），goal_blocked一律按多段末点的方式逐个检查替代落点（alt_goal，最多5次，示教除外，不弹窗），no_nav仍等待，不混用多段跳点策略；单点/示教的90秒预算只数“处理问题”的真实时间（WaypointRun.trouble_s，不被任何事件重置），满90秒停一次再继续、满180秒放弃（TROUBLE_BUDGET事件，网页提示），整段正常行走不限时；但blocked/start_blocked的局部脱困三类任务共用，见下。原规划、LIO、感知、速度仲裁和安全门职责不变。

运行切换日志在runs/<run>/route_decisions.jsonl，含圈次、原点/候选、原服务检查结果、转换原因和实际进展时间。完整规则、参数边界和验证入口见[导航恢复现状](导航恢复现状.md)。

局部受困按原因分流（2026-11-11，已实现；多点、单点、示教共用同一份LocalRecovery）：目标受阻/目标区域占据仍走多点的中间跳点、末点替代；机器人自身受困走本点局部脱困，不因此跳点。blocked（局部跟随全部候选碰撞，有体素/近期证据记忆）：后退→转向；start_blocked（全局规划起点不可用，全局图无体素记忆，盲目后退无依据）：转向→换位置，不后退。阶梯只定义一次（task_logic.LOCAL_LADDERS）、只执行一次（go2_task/local_recovery.py），多点RouteExecution与单点/示教的LegacyLocalHost只是宿主。换位置是机器人周围0.5/0.8米的临时点，每个候选由原/mot_nav_check从当前位姿检查（候选与原目标一并检查），到达后恢复原目标，不改写原航点；示教path任务不能换位置，转向后即视为阶梯用尽。后退成功=按loc_pose狗真的后退约0.3米（recover_backup_m 0.3减local_backup_tol_m 0.03），不是按时间；转向须同方向实际转≥local_turn_min_effect_rad(0.5rad)；换位置须到达临时点；均不采信RECOVER_DONE=ok。超时（local_step_timeout_s 20秒、local_relocate_timeout_s 15秒）只是看门狗。后退速度用mot_recover 0.15m/s（低于0.13m/s启动即报错，safe_gate 0.12以下会置零）。阶梯按“本点×原因”计数，重规划/新goal编号不重置本点用时、30秒空间进展窗口或阶梯位置，只在换点/下一圈重置；无效步骤直接进下一级，阶梯用尽走原fail分流（多点中间点跳过/末点替代；单点/示教SKIP并走旧的一次ROUND_RETRY）。单点/示教的其它原因（no_path、goal_blocked、no_progress、no_nav）仍用旧task_logic阶梯。safe_gate对自动纯转向增加旋转扫掠检查（扫描点将进入转动中的机身矩形则置零，已在机身内的点忽略，仅点距判断、无高度/腿模型）；被拦的转向计为limiting，mot_recover可报blocked。

控制链单层（回答“架构是单层吗”）：TaskExecutor决定 → mot_recover（/mot_recover_cmd）或发往原mot_nav的临时目标（候选经原/mot_nav_check检查） → mot_cmd_mux → safe_gate（唯一限速）。阶梯只在task_logic.LOCAL_LADDERS定义一次，只由LocalRecovery执行一次，RouteExecution与LegacyLocalHost是它的宿主；没有第二份阶梯或并行控制路径。

sim_bridge不再按定位状态门控速度（2026-11-11按用户要求删除）：只剩使能与步态就绪；定位DEGRADED/LOST时遥控、恢复动作和导航指令都会送到狗。safe_gate仍是自动指令的唯一限制者（LOST时零速），手动不受限。localisation_ready()只用于一次性的SIM_READY启动判定。详见[导航恢复现状](导航恢复现状.md)“已知问题”。
