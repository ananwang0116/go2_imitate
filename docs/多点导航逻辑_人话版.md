# 多段巡航 + 单点导航：现在到底怎么跑（人话版，2026-11-12 更新）

依据：`task_executor.py`、`route_execution.py`、`route_policy.py`、`local_recovery.py`、`mot_nav.cpp`，以及 run 20261112_144912_nav 的日志。写的是**代码现在实际做的事**。没验证的会标“没验证”。

## 先说结论

- 多段和单点现在用**同一套**“没进展”判据；**绕大圈上限只用于多段**，单点/示教想绕多远都可以走，整段也不限时（只限“处理问题”的累计时间，见下）。区别还有放弃后做什么。
- **多段（≥2 个点、没有示教路线）**：快放弃。放弃就跳到下一个点，不做恢复动作，最后一点先找替代落点。
- **单点（网页点一下 / 探索提议）和示教路线**：先做恢复动作再试，放弃后整个点再来一遍。

共用：到达判定、90 秒预算、定位 LOST/DEGRADED、狗自己被卡住时的脱困阶梯。

---

# 第一部分：一个点怎么算“到了”

1. 把目标（坐标、到达半径、可选朝向）交给 mot_nav，用全局 A* 规划，跟随器走。途中新障碍它自己绕，**不算失败**。
2. **多段的中间点：经过就算过。** 进入 **0.6 米** 范围就算到，**不再原地转朝向**。用户给的朝向只画在网页上，中间点不强制。
3. **最后一个点（和单点）**：进入自身半径（默认 0.4 米）；如果带朝向，原地转到朝向（最多 8 秒）才算到。

# 第二部分：什么时候放弃一个点

| 触发 | 具体含义 | 多段 | 单点/示教 |
|---|---|---|---|
| 目标区域被占 | 每秒问原 `/mot_nav_check`，连续约 1 秒说半径内没有可站位置 | ✔ | 不问，靠 mot_nav 报 `goal_blocked` |
| 导航明确失败 | mot_nav 报 FAILED（无路径、目标被挡等），保持 0.5 秒；`blocked`/`start_blocked` 先走脱困阶梯 | ✔ | ✔（按原因做恢复动作） |
| **没有进展** | 近 20 秒里狗从没离开过“它现在所在位置”0.4 米以外 | ✔ | ✔（再确认 2 秒） |
| **绕大圈** | 见下 | ✔ | ✗（不限制） |
| 90 秒预算 | 每点最多 90 秒（暂停不计），脱困和找替代落点也算 | ✔（整段用时） | ✔（只数问题处理的时间，满 90 秒停一次、满 180 秒放弃） |

**“没进展”不看路径长度变化**（重规划会把它搅乱），只看狗的真实位置。蠕动、原地转、小幅摆动都在 0.4 米圆内，会被判无进展；原路退出死胡同算有进展。

**最后一个点（含替代落点）有一条豁免**：狗离目标不超过“到达半径 + 0.15 米”时，在小范围精细对位不算停滞（90 秒预算兜底）。中间点没有这条豁免。

**“绕大圈”怎么判（新）：**
- 每个点记录原规划器“到目标的路径代价”的**最小值 best**，代价来自每秒的目标检查返回的 `leg_m`（只用于多段）。
- 代价超过 `max(best×1.5, best+2 米)` 并持续 3 秒，就判“绕大圈”，放弃这个点（`detour_too_long`）。
- 开局前就存在的长路（门、房间、早就摆好的箱子）进入 best，是**允许**的。只拒绝“后来因为新障碍才变长的路”。
- 它和 `no_path` / `goal_blocked` 是两类：后者是“根本没路 / 目标封死”，前者是“有路但太长”。
- 阈值是用原 run 的规划长度离线回放调的：原 run 约 17 秒后就会拒绝（以前要 60 秒），**没在物理里系统验证**。

**狗自己被卡住怎么办**（共用）：
- `blocked`：后退约 0.3 米 → 转向。
- `start_blocked`：转向 → 换到附近经检查的临时位置（不后退）。
- 按定位的实际位移判断是否生效；阶梯用完才算这个点失败。脱困结束后给 10 秒进展宽限。

# 第三部分：放弃之后

**多段：**
- **中间点**：标记跳过，撤掉旧目标，下一个点从狗当前位置重新规划。
- **最后一个点**：先找替代落点——原点周围 0.5 / 1 米两圈内，每个候选单独让原检查服务检查，**候选的路径代价超过同样上限的也拒绝**（不会换成另一个要绕同样大圈的点）；最多试 5 次；替代点到达半径不超过 0.15 米，保留原朝向。
- 单次任务走完一圈就结束，不回头补跑。循环任务下一圈重新尝试**所有原始点**；整圈一个都没到就停止循环。

**单点 / 示教（2026-11-12 改）：**
- `no_path`（规划器找不到路）和 `no_progress`（没进展）：**后退 0.3 米 → 转向**（按定位的实际位移判断是否生效）；`no_nav` 仍是等 2 秒。阶梯用完 → 标 SKIPPED，然后**整个点再来一遍一次（用时清零）**。
- `goal_blocked`（目标点封死，不分起点还是走近，没有特殊处理、不弹窗）：像多段最后一点——围绕原目标 0.5 / 1 米两圈的候选，逐个从狗当前位置经原检查服务检查，通过才下发，最多 5 次，到达半径更小、保留朝向。全都不行就按普通放弃处理（SKIPPED，照旧一次重试）。示教路线不能换目标，直接按阶梯用尽处理。
- 不限制绕大圈，也**不限制整段用时**：路再长也走。90 秒预算只数“处理问题”的真实时间（正在做恢复动作、被报了失败、没进展、不动超过 5 秒），这个时钟只往前走，**任何事件都不会把它清零**。问题处理累计满 90 秒：先停止，网页提示后再继续一轮；累计满 180 秒：放弃该点并提示，不再重试。

**定位异常：** LOST 撤运动并暂停（计时也暂停）；DEGRADED 只降速到 50%。

# 第四部分：网页显示（新）

- 多点任务运行时，除了当前这一段蓝色实线，**后面各点之间的航段**也用蓝色虚线显示。路径来自原 `/mot_nav_check` 对“当前目标及之后各点”的规划，每 2 秒刷新，只用于显示，不参与控制。
- 运行时每个编号圈里画一个**黑色箭头**，就是你设置的朝向（原来运行时只有圈和编号）。
- 圈的大小是有效半径：中间点 0.6 米，最后一点按自身半径。
- 没做：运行前（还在编辑/检查时）的航段预览；循环模式里“最后一点回到第一点”的那一段。

## 我仍觉得可能“不对”或可疑的地方

1. **规划航向为什么来回摆，根因没查。** 现在是更快放弃，不是修好。
2. **0.6 米、1.5 倍/2 米/3 秒、20 秒/0.4 米都是我估的仿真阈值**，没有真机依据。
3. **绕大圈判据依赖规划器的代价抖动。** 地图证据 30 秒过期会让代价突降又突升；3 秒保持和 best 取最小值能挡一部分，但可能误拒或漏拒，需要更多 run 验证。已见到另一个 run（20261112_151920_nav）里离线回放会在约 53 秒触发，是否合理没核对。
4. **中间点不再转朝向**：如果你某个中间点确实要朝某个方向（比如拍照），现在做不到，需要给点加一个“必须转朝向”的属性。
5. **替代落点 0.15 米半径可能和 20 秒窗口冲突**：狗在目标 0.4 米内慢慢对位但没进 0.15 米，会被判无进展而放弃。没验证。
6. **单点的“换位置”只挪半径一半**（约 0.2 米），基本不改变处境。
7. **跳过 ≠ 经过。** 点被跳过后，狗可能已离路线很远，下一个点从它当前位置直接规划，不会先回路线。

# 附：实时障碍的保留时长（2026-11-12）

- 同一格**连续被占据不足 3 秒**的是**动态**障碍（走过的人、孤立噪点），网页**黄色**，最后命中后 **5 秒**消失。
- 连续被占据 **3 秒以上**的是**静态**障碍（箱子、墙），网页**青色**，最后命中后 **90 秒**消失。
- 在视野里被射线再次穿过、看到是空地，不管哪种都会很快清掉；时长只管“离开视野”的格子。
- 两种时长在网页「图层」面板可以实时调（动态 1–30 秒、静态 10–600 秒），只对本次运行有效。
- 不识别物体，只看这一格被连续占据了多久。两种都阻挡规划。
