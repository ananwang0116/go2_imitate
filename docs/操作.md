# 操作

每次启动都会先停止上一轮v4网页、gzserver、gzclient、控制器和ROS节点，确认端口释放后创建新网页。即使上次网页被强制杀死，也会按已保存的会话归属清理残留。地图和运行记录不删除。

电脑启动：`cd /home/an/go2_v4 && bash tools/sim_up.sh`。

1. 打开 http://127.0.0.1:10087/。
2. 系统中选 `my_map`，点击「打开 Gazebo 并启动导航」。
3. 等待模型生成、控制器加载、5秒站立和trot交接完成，仿真位姿正常后再操作。启动阶段日志在系统卡片与run/startup.jsonl。
4. 在「任务」设置目标或航点并执行。默认使用Leg-KILO定位；出生点配置仅作为loc_align的初始提示，匹配成功后才开放任务。
5. 网页「停止」关闭模拟器的服务端和窗口及本次导航节点；窗口关闭也会结束本次仿真。
6. 在启动网页的终端按 Ctrl-C，关闭网页与它仍在管理的仿真。

网页 3D 点云空白是当前阶段的预期行为。它与 Gazebo 的 3D 场景窗口是两种不同的显示。

## 排查

- 启动失败：看系统卡片日志以及 `runs/_web/launch_*.log`。
- 缺少 Gazebo 插件：本机依赖是 Gazebo 11 和 `ros-humble-gazebo-ros-pkgs`；当前环境已有安装。
- 没有窗口：确认在有 DISPLAY 的桌面会话启动。检查 GUI 日志，不自动换成其他可视化软件。
- 另一仿真占用锁：先在拥有它的网页停止，不按进程名字强杀。
- 原点或墙体不一致：确认换入的地图确实来自当前 world；本项目初始 my_map 与 internship 地图哈希一致。

保留 `maps/` 根目录的原始地图资料；运行用副本是 `maps/my_map/map.yaml` 与 `map.pgm`。


## 实时导航与前沿探索

1. 点击顶部间隔开的「实时导航」按钮，在当前页面内切换到实时控制卡片；URL、原画布和整体样式保持不变。若固定地图仿真仍运行，先点「停止仿真」，等待收尾完成；不会创建第二套Gazebo。
2. 点击「启动实时导航」。仍使用当前custom.world和Go2动力学模型；地图全未知开始，等站立/trot、真实仿真IMU预热、Leg-KILO定位、扫描和在线地图就绪。
3. 系统卡片下方、与「3 任务」子页签同一位置选择三种方式，依次完成「1 设置任务 / 2 执行任务」：
   - 「手动遥控」：取消自动任务，待状态切为手动且任务空闲，使用WASD/QE或按住屏幕按钮；松开停止。手动没有障碍防撞限制。
   - 「单点导航」：点击已观测空闲区域选目标，可按下拖动指定最终朝向，再按「前往目标」。只点击时不强制终点朝向。选定后点坐标旁的「✕」删除目标并重新选取；执行单点任务时先暂停，再删除。未知区或没有机身余量的目标被拒绝；路径检查由原mot_nav完成。
   - 「前沿探索」：点击「开始探索」，系统依次选择前沿候选，经原规划器检查后由task_executor执行。没有安全可达前沿时会停在“暂无可达前沿”，可手动补扫后再开始。
4. 地图图例：实时雷达扫描为红色，最近障碍为青色，持久观测地图占据为深色，未观测为灰色；实时障碍分两种颜色：黄色=动态、青色=静态，各自的保留时长可在「图层」里调（默认动态5秒、静态90秒，持续看到会续期）。持久地图不按这些时长删除。
5. 「暂停」只取消运动任务，继续扫描建图；「急停」还发送零速并调用仿真停机服务。切换手动会取消自动任务。
6. 控制页面关闭/标签页隐藏会请求暂停；仅仅点到别的窗口（比如Gazebo）导致页面失焦不再暂停（2026-11-12改，手动遥控按住的键仍会在失焦时松开）；控制页面超过3秒没有心跳也会自动暂停，另一个查看页面不能代替续租。恢复后必须手动重新开始。定位、扫描、任务或导航图失联同样暂停。
7. 宽屏左侧「定位与实时地图」替换地图列表，左栏加宽至280px，显示定位状态、位姿、观测面积和前沿候选，不列定位来源；窄屏自动移入右侧。安全状态“待命”表示当前没有运动命令，不是缺少定位。默认定位来自Leg-KILO（LIO：仿真点云+IMU）；Gazebo真值只保留设备反馈/评价。
8. 「保存当前地图快照」写入本次run的`maps/<唯一时间>/map.yaml`和`map.pgm`，路径显示在页面。不会覆盖maps/my_map。当前快照不自动加入固定地图列表。
9. 停止仿真并等待完成后，可直接点击顶部「2 定位 / 3 任务」切回固定地图工作区；关闭Gazebo窗口、核心节点退出或网页关闭均按同一归属机制收尾。

实时网格当前固定30m×30m、5cm分辨率，范围[-15,15)m；当前world在范围内。尚未实现网格自动扩展、腿里程计融合或全world覆盖保证。

```bash

source ./go2_env.sh
python3 tools/run_bounded.py 120 colcon build --symlink-install --packages-select go2_sim go2_web

```

集成检查使用自有10088测试网页，拒绝占用的仿真11348；运行前在拥有当前会话的网页中停止仿真。只核实并关闭测试自身的进程组/会话，结束检查进程与端口。`run_bounded.py`默认给通用任务退出收尾45秒，SLAM仿真检查使用85秒，可用`GO2_WATCH_STOP_SECONDS`调整；内层就绪、执行、停止预算应小于外层总限。日志写runs，阶段结果和未验证项同时维护record.md及docs/records。


## SLAM定位说明

固定图与实时模式默认均启用Leg-KILO；网页“定位来源”应显示Leg-KILO·LIO。站立之前不向SLAM发输入，防止落地/站起过程污染初始化。SIM_GAIT_READY后先开放IMU，积累至少50帧再发原始轴系点云；等待loc_pose连续OK2秒。不要把“启动了进程”当作定位就绪。

地图对齐或定位跳变时自动任务停下；实时地图在跳变时清空重建，不沿用旧坐标的障碍。SLAM退出整栈停止，不能继续用Gazebo位姿驱动。SLAM数据保存在run/kilo，runtime和轨迹/全局图在结束后保留；短程仿真证据不代表长距离或真机精度。

关闭网页/再次sim_up会等待本轮SLAM导出。内层导出40秒、管理器55秒、网页65秒、启动器75秒；不要按进程名强杀。历史`ground_truth`为显式终端诊断模式，不是正常网页默认。


## 手动给初始定位与实时导航入口

在固定地图控制台顶部点击「2 定位」，右侧「设置初始定位」卡片始终保留。导航启动后，点击「在地图上设置初始位置」，在地图上机器人所在处按下并拖向朝向，松开后点「开始定位」。等待“对上了/使用提示位置”的反馈。该操作向原loc_align提供初始提示，连续定位仍由Leg-KILO负责；没有先选位置时“开始定位”呈禁用状态。

「实时导航」按钮位于顶部「地图 / 定位 / 任务」右侧，留有间隔，采用浅青底、深青文字和指南针图标。它只切换当前页面右侧控制卡片和原有画布，不打开另一个页面。小窗口会调整顶栏布局，入口保留。切换工作区不自动创建第二套仿真；固定地图仍运行时，先在系统卡片停止，再启动实时模式。


提交初始定位后，应看到顶栏“定位中”和卡片“正在定位/正在对齐”；loc_align返回且新坐标已生效后显示完成、弱对齐或失败。弱对齐会提示检查红色扫描点与墙面；失败或8秒超时可重试，不会一直显示旧“已定位”。尚未选位置时“开始定位”禁用；活动任务需先结束。

模式停止/重启时网页清空本轮位姿和图层。新实时模式在Leg-KILO新位姿到达前显示“等待本轮定位”，随后以本轮SLAM起点为零附近。旧模式移动后的位置和手动初始定位偏移都不会带到下一次仿真。


## 目标、定位分数与轨迹

目标拖动方向以地图世界坐标保存，蓝色箭头显示指定最终朝向，中心不再显示E；未指定朝向则仅显示圆点。固定地图的定位条和顶栏百分比来自持续运行的`loc_map_check`激光/地图吻合分数，每秒更新；分数不是启动进度，环境吻合时保持100%是正常现象。超过3秒未收到分数显示等待数据，不沿用旧分数。实时地图显示LIO健康，不冒用正在增长地图的自吻合率。

固定和实时导航只显示执行中的蓝色规划路径，到达后消失；不显示红色已走尾迹。建图示教与已选示教路线的原有橙色线保持原样。后台实际位姿轨迹仅供诊断记录。位姿以10Hz采集/轮询，画布使用150ms延迟在已收到的真实位姿之间插值，越过最新帧时停在该帧，不外推；定位缺失、对齐中或大跳变即重置显示队列。该平滑仅影响显示，不改变任务、避障或反馈位姿。

启动仍依赖顺序推进。单个`sim_startup`进程逐个load/configure三个控制器，任一步失败即结束；成功后复用原始`StandCommand`站立、反馈与激活逻辑，再交接原trot控制器。5秒站立、IMU至少50样本、连续2秒健康门槛不缩短。`startup.jsonl`提供阶段墙钟与耗时；详见运行日志的SIM_GAIT_READY和SIM_READY。


## 任务页操作与扫描修正

「3 任务」有四个子页签：多点巡航、单点前往、示教路线、遥控。单点前往使用整行「在地图上选目标」按钮，拖动设置朝向，✕清除重选。遥控从各任务页面底部移到第四页签；仍是同一个键盘/手柄/速度面板，控制接口、松键停止、活动任务锁与命令/反馈看门狗保持原样。

v4只运行同一个`per_scan`扫描节点，固定图与实时模式共用。点云最多等待1秒自身时间戳的机身TF，缺少就丢弃，不用latest姿态。每帧重新拟合地面，拟合不足用base_footprint的当前零高度参考，不复用旧机身坐标中的地面斜率。当前仿真世界地面为水平面；未验证任意坡地。Leg-KILO与原导航C++算法保持不变。

多点任务：前面的点被确认占据、导航失败或20秒无实际空间推进（20秒内离当前位置始终不足0.4米）时本圈跳过；仅最后一点检查附近替代落点（默认中心偏移不超过1米）。中间点进入0.6米范围即算经过（不转朝向），最后一点保持原半径并转到朝向；多点任务里路径代价（原规划器A*长度）比最低值高出1.5倍或2米并持续3秒视为绕大圈，放弃该点；单点和示教不限制绕大圈。单点点了走不了的位置（goal_blocked）不再弹窗：像多段最后一点那样逐个检查替代落点，都不行就按普通放弃处理。单点/示教不限制整段用时，只限制处理问题的总时间：问题处理累计满90秒会先停止并提示再继续，累计满180秒放弃并提示。运行时地图上除当前蓝色路径外，后续各点之间的航段以蓝色虚线显示，圈内的箭头是你设置的朝向。每点90秒总预算，定位“偏低”不放宽，“丢失”撤运动并暂停。一次巡航结束后不补跑被挡点；循环巡航下一圈仍尝试每个原始目标，末点也不保留替代坐标。整圈零到达时仍停止循环，避免空转。

“恢复N次”是累计次数，“本点用时”是累计非暂停用时。多点末点的次数表示已下发的合格替代候选；单点/示教仍为原恢复动作次数。实时障碍：动态（黄）最后命中后5秒、静态（青）90秒，持续命中续期，可在图层面板调；过期消失不等于空闲。修改后重启仿真加载执行器。

排查时看runs/<本次运行>/route_decisions.jsonl：transition记录from_phase/to_phase/reason，check_result记录可达性理由，progress同时记录实际pose、stall_s与remaining_m，round_start记录原始航点。完整现行规则见[导航恢复现状](导航恢复现状.md)。

局部受困按原因分流（2026-11-11，已实现；多点、单点、示教共用同一份LocalRecovery）：目标受阻/目标区域占据仍走多点的中间跳点、末点替代；机器人自身受困走本点局部脱困，不因此跳点。blocked（局部跟随全部候选碰撞，有体素/近期证据记忆）：后退→转向；start_blocked（全局规划起点不可用，全局图无体素记忆，盲目后退无依据）：转向→换位置，不后退。阶梯只定义一次（task_logic.LOCAL_LADDERS）、只执行一次（go2_task/local_recovery.py），多点RouteExecution与单点/示教的LegacyLocalHost只是宿主。换位置是机器人周围0.5/0.8米的临时点，每个候选由原/mot_nav_check从当前位姿检查（候选与原目标一并检查），到达后恢复原目标，不改写原航点；示教path任务不能换位置，转向后即视为阶梯用尽。后退成功=按loc_pose狗真的后退约0.3米（recover_backup_m 0.3减local_backup_tol_m 0.03），不是按时间；转向须同方向实际转≥local_turn_min_effect_rad(0.5rad)；换位置须到达临时点；均不采信RECOVER_DONE=ok。超时（local_step_timeout_s 20秒、local_relocate_timeout_s 15秒）只是看门狗。后退速度用mot_recover 0.15m/s（低于0.13m/s启动即报错，safe_gate 0.12以下会置零）。阶梯按“本点×原因”计数，重规划/新goal编号不重置本点用时、30秒空间进展窗口或阶梯位置，只在换点/下一圈重置；无效步骤直接进下一级，阶梯用尽走原fail分流（多点中间点跳过/末点替代；单点/示教SKIP并走旧的一次ROUND_RETRY）。单点/示教的其它原因（no_path、goal_blocked、no_progress、no_nav）仍用旧task_logic阶梯。safe_gate对自动纯转向增加旋转扫掠检查（扫描点将进入转动中的机身矩形则置零，已在机身内的点忽略，仅点距判断、无高度/腿模型）；被拦的转向计为limiting，mot_recover可报blocked。排查看route_decisions.jsonl的local_step/local_result（含effect、effective、local_steps；单点/示教的行带policy=single_or_teach）。

已知问题（待用户决定）：仿真里若地图外障碍（如激光附近的未建图箱体/墙）使吻合分数降到0.45以下，定位变为DEGRADED，sim_bridge只在定位OK时转发速度，狗会完全不动，后退/转向/导航都没有效果，多点会以no_spatial_progress跳点。该门槛本次未改；详见[导航恢复现状](导航恢复现状.md)“已知问题”。
